## Critical Constraints (repeat these to every implementer)

- `backend/engine/` — **ZERO FastAPI imports**. Verify with: `grep -r 'from fastapi\|import fastapi' backend/engine/`
- **Never store raw message text** — SHA-256 hash only (`text_hash = hashlib.sha256(text.encode()).hexdigest()`)
- **Duress login response is IDENTICAL in shape AND timing to normal login** — check BOTH pin hashes always with `secrets.compare_digest`; never short-circuit on the first match
- **`shared/reason_codes.json` and `i18n/en.json` must NOT be modified**
- **All reason/advice codes in API responses must exist in `shared/reason_codes.json`**
- **All paths in DB and file operations must be absolute** (`os.path.abspath`, `os.path.dirname(__file__)`)

**Key decisions:**
- UUID PKs generated by Python (`uuid.uuid4()`), stored as String in SQLite for portability.
- Opaque bearer tokens (UUID string), stored in `UserSession.token`. No JWTs — simpler for MVP.
- PIN hashing via `passlib[bcrypt]` with `rounds=12`. Both PINs hashed before storage; plain text never persisted.
- Duress timing: in `POST /login`, fetch user, then run `bcrypt.checkpw` on BOTH `pin_hash` AND `duress_pin_hash` regardless of which matched first. Use `secrets.compare_digest` on the boolean results. This prevents timing oracle.
- `GET /accounts/me` returns `balance='0.00'` for all users in MVP (no real balance tracking). Decoy returns same shape.
- `decoy/generator.py` seeds `random.Random(hash(user_id) & 0xFFFFFFFF)` — deterministic, same output every call.
- i18n files loaded from absolute path at runtime; never imported as Python modules.

## FEAT-002 — Pure-Python Risk Engine, Classifier, /scan Endpoint, Training Data

**What:** All 15 rule signals, language detection, email checks, URL check (mock + live modes), 60+ scam samples, 60+ legit samples, scam library JSON, classifier training script, classifier module with lazy loading, score blending in real `/scan` endpoint, LLM fallback stub, evaluation script, and rules tests. Depends on FEAT-001.

**Files to create/replace:**
```

backend/engine/url_check.py        (no FastAPI)

backend/engine/rules.py            (no FastAPI — 15 signals, full keyword lists)
backend/engine/classifier.py       (no FastAPI — lazy-load .pkl)
backend/engine/llm_fallback.py     (no FastAPI — no-op when LLM_ENABLED=false)
backend/routers/scan.py            (REPLACE stub with real implementation)
scripts/train_classifier.py
scripts/evaluate_classifier.py
data/scam_samples.json             (65+ entries, 5 categories, en+zu)
data/legit_samples.json            (65+ entries)
data/scam_library.json             (10-15 entries)
backend/tests/test_rules.py        (30+ test cases)
```

**Key decisions:**
- `rules.py` loads weights from `shared/reason_codes.json` at import time via absolute path (`os.path.join(os.path.dirname(os.path.dirname(os.path.abspath(__file__))), 'shared', 'reason_codes.json')`). This is the single source of truth.
- Score cap: `min(100, sum(matched_signal_weights))`. If sum > 100 the engine clips. The classifier adds on top via blending, not stacking.
- Blending: `blended = round(0.6 * rules_score + 0.4 * (classifier_probability * 100))`. Both weights read from env with defaults.
- Tier enforcement: if `blended >= 70` but `len(reasons) == 0`: cap score at 69 and tier becomes CAUTION.
- `classifier.pkl` uses absolute path derived from `backend/engine/classifier.py`'s own `__file__`. On `FileNotFoundError`: log warning, return `0.5` (neutral probability).
- LLM fallback: only fires when `LLM_ENABLED=true` (env) AND `30 <= blended <= 60`. Default is disabled.
- `url_check.py` MOCK_BAD_DOMAINS includes at least 25 domains and the full set of URL shortener domains.
- Lookalike domain check uses Levenshtein distance ≤ 2 against 10 legitimate SA/Zim/financial domains.

## FEAT-003 — Transaction Rules, USSD, SMS, Panic, Login Guard, Library Endpoints

**What:** Transaction rules engine (6 rules), real transaction endpoints, USSD stateless state machine, SMS inbound/outbox, panic endpoint, login-guard endpoint, scam library endpoint. All replace FEAT-001 stubs. Depends on FEAT-001 + FEAT-002.

**Files to create/replace:**
```

backend/routers/transactions.py         (REPLACE stub)
backend/routers/panic.py               (REPLACE stub)
backend/routers/login_guard.py         (REPLACE stub)
backend/routers/library.py             (REPLACE stub)
backend/routers/sms.py                 (REPLACE stub)
backend/routers/ussd.py                (REPLACE stub)
backend/tests/test_transaction_rules.py
```

**Key decisions:**
- `AFTER_RISKY_MESSAGE` triggers from two sources: (a) ScanResult with tier=HIGH_RISK in last 30 min, OR (b) `user.login_guard_alert_until > utcnow()`. The router passes both signals to `check_transaction`.
- Transaction `send` in duress mode: write `Transaction(is_decoy=True, status='decoy')`. The real user's balance is never modified (no real balance column in MVP). Returns HTTP 200 with success shape.
- USSD is fully stateless: all state is in the `text` parameter. Session IDs are logged but not stored.
- USSD screen strings are at most 160 characters. Look up from `i18n/{user.language}.json` using keys like `ussd.menu.title`, `ussd.check_message.result.high_risk`.
- SMS inbound `'1'` command returns the user's last ScanResult formatted to ≤160 chars (≤120 for Hindi to account for UCS-2).
- Library endpoint loads `data/scam_library.json` from absolute path at request time (not cached at startup) so it's easy to update.

**Verify:**
